# Ashbound v0.6 — Expedition Route Graph & Node Identity

## 1. Delivery revision

This document describes the v0.6 implementation based on `b3843c4`. The final delivery commit is reported by Git and in the completion response; debug-modified runs remain visibly flagged in telemetry.

## 2. Verification result

Unity 6000.4.11f1 compiled the generated content. EditMode passed 40/40, PlayMode passed 15/15, the Windows x64 Mono development build succeeded, and the executable remained alive during an eight-second smoke launch. These checks establish integration, not balance.

## 3. Route graph architecture

`ExpeditionRegionDefinition` owns graph variants. `ExpeditionRouteGraphDefinition` owns topology and constraints. `ExpeditionNodeDefinition` owns stable identity, risk, reward category, outgoing IDs, encounter/space references, service definitions, reward flags, and telemetry tags. `ExpeditionRouteRuntime` selects a seeded variant and owns discovery, completion, visibility, votes, and the current node. UI reads this runtime and does not decide topology.

## 4. Implemented node types

The playable set is Normal Combat, Hard Combat, Elite, Treasure, Relic, Merchant, Rest, Event, Challenge, and Boss. `Secret` remains an enum extension seam but is not implemented in this milestone.

## 5. Prototype region structure

The Cinder Vault has three authored ten-node variants. Each begins at Normal Combat, branches toward Hard or Treasure, branches again through Relic, Elite, or Merchant, reconverges through Rest or Event, proceeds through Challenge, and ends at a regional Boss. A run visits one path rather than every node.

## 6. Generation and validation constraints

Graph selection is deterministic from the run seed. Validation requires 8–10 nodes, unique non-empty IDs, valid edges, a reachable Boss, no non-Boss dead ends, no orphans, at least three combat nodes, no more than one Rest or Merchant in these graphs, a maximum repeated type, and required encounter, combat-space, and reward/service references. Invalid graphs throw when a route runtime is constructed.

## 7. Reward cadence

The former combat → relic → equipment sequence is removed from ordinary progression. Normal Combat pays run resources. Hard and Elite pay stronger resource packages and equipment drafts at different qualities. Relic owns the relic draft. Treasure owns targeted equipment with variant rules. Merchant sells finite stock. Rest provides one bounded utility action. Event outcomes vary. Challenge pays success or consolation resources. The regional Boss grants its authored boss reward.

## 8. Treasure variants

`TreasureDefinition` contains weighted variants: Standard Cache 52, Sealed Vault 14, Cursed Chest 9, Greedy Cache 10, Common Mimic 8, and Corrupted Cache 7. The total is 100. Costs and weights are authored data. Standard provides one targeted equipment reward; Sealed requires run currency; Cursed spends bounded current health and adds pressure; Greedy permits up to three separately accepted rewards; Corrupted uses a rare run cost and next-combat pressure.

## 9. Mimic implementation

Common Mimic is an `EnemyDefinition` using the existing Assassin movement, targeting, telegraph, damage, death, and encounter pipeline. Opening the Mimic variant starts the authored `mimic-reveal` encounter in the existing space. Defeat promotes reward quality by one step and records encounter/result telemetry. Future tiers can be additional variants and enemy definitions.

## 10. Merchant implementation

`MerchantSession` rolls finite stock from profile-eligible weapon, armor, and relic pools plus recovery. Quartermaster stock and reroll-discount hooks apply. Purchases and at most two rerolls spend `RunResources`; persistent Hub currency is not touched. Sold entries cannot be purchased twice. `ProgressionEconomy.MerchantAlwaysExceedsSalvage` remains tested for every rarity and gear class.

## 11. Rest and Temper

Rest offers exactly one choice. Rest restores a bounded health fraction and consumes the reduced-healing-until-Rest modifier. Temper upgrades one equipped weapon or armor item by one rarity step, applies a modest prototype stat adjustment, and cannot exceed Epic at this node. Salvage/Repair grants a small run-resource package and modest recovery. Infirmary and preparation recovery hooks affect Rest.

## 12. Events and Challenges

Five data-driven events are included: Abandoned Expedition Cache, Broken Shrine, Wounded Survivor Trace, Unstable Rift, and Collapsed Armory. Each has 2–3 choices with optional visible/hidden outcomes, run costs, health costs, rewards, information, drafts, or combat escalation. Three challenge definitions exist; route variants use timed or rule-labeled encounters with success and consolation outcomes. Failure does not end the run.

## 13. Multiplayer route voting

Solo selection resolves immediately. With 2–4 local players, each locked roster ID must submit a vote. The majority wins. `VoteTieBehavior` configures host tie-break or seeded random selection. The route UI shows player vote indicators, counts, the current voter, node risk, reward hint, and 1/2/3 plus A/B/Y controls.

## 14. Regional and final Boss gating

The graph Boss is a regional milestone using an ordinary combat-state encounter and `BossRewardDefinition`. It cannot trigger corruption. Completion opens a visible final-area approach gate. Crossing that gate enters the existing `BossFight`, spawns the true Cinder Regent, and preserves Boss death → corruption transition → local PvP or solo Reflection.

## 15. Telemetry

Local schema 5 adds graph ID, node type/risk/reward category, offered and chosen routes, party votes, node duration/damage/remaining HP/resources, Treasure variant/cost/reward count, Mimic encountered/defeated, Merchant spend/rerolls, Rest/Event choices, Challenge result, Boss reward, final-Boss entry, and time in route, Treasure, Merchant, Rest, Event, and reward menus. Files remain local under `Application.persistentDataPath/Telemetry`.

## 16. Debug tools

F1 → Route can start a deterministic seed, regenerate, reveal or limit route information, add run currency, jump by node type or exact ID, force every Treasure variant including Mimic and Cursed Chest, and display graph validation. Existing Equipment, Meta, and Ecology pages remain available.

## 17. Files added and modified

New runtime/data code lives in `Assets/Scripts/Routes`, with route enums in Core domain. Generated definitions live under `Assets/ScriptableObjects/Routes`, `Treasures`, `Merchants`, `Rests`, `Events`, `Challenges`, and `BossRewards`; Common Mimic adds one enemy and encounter asset. `RunManager`, `RoomDirector`, HUD, debug menu, telemetry, reward draft, progression service, content builder, tests, catalog, and health cost handling were extended. Existing v0.5 spaces and ecology data remain intact.

## 18. Known issues and intentional limits

The route map and location panels use immediate-mode graybox UI. Non-combat locations reuse the current region-space presentation rather than authored final camps or shrines. Challenge labels are broader than the one timed runtime failure condition. Merchant recovery is not a separate consumable inventory. Route selection is local only. No five-region campaign, online networking, final art, or cloud persistence was added.

Route pacing, reward economy, Mimic frequency, Treasure distribution, combat-space scale, and challenge timings are not claimed balanced. The weights are exposed prototype values for human iteration.

## 19. Human playtest checklist

1. Run at least three seeds and confirm graph title/event/encounter variation.
2. Compare a Hard-first path with a Treasure-first path; note health, resources, and build clarity.
3. Test every Treasure variant through F1, including stopping Greedy Cache after each claim.
4. Buy, reroll, equip, and salvage Merchant gear; verify no run-resource profit loop.
5. Try Rest, each Temper target, and Salvage/Repair at low and high health.
6. Trigger all five events and both clear and failed Challenge outcomes.
7. Vote with 2, 3, and 4 physical players, including ties and controller disconnects.
8. Confirm regional Boss death does not start corruption; cross the final gate and finish the true Boss flow.
9. Inspect schema-5 JSON for complete node and menu records.
10. Walk v0.5 spaces and transitions for camera, spawn, projectile, obstacle, and world-continuity problems.

## 20. Recommended next milestone

Run a focused v0.7 human validation and tuning pass before adding more regions. Use telemetry plus observation to tune route information, reward frequency, Merchant prices, Treasure weights, health costs, Challenge timers, and combat-space scale. Then add controller-first menu focus/navigation and author non-combat location presentation. Expansion to multiple regions should wait until one-region choices remain readable and economically stable across solo and local co-op.

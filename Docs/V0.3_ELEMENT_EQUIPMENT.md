# Ashbound v0.3 — Element Identity & Equipment Foundation

This milestone extends the existing v0.2 run and combat architecture. It does not add networking, final art, permanent progression, or additional maps. All tuning is prototype tuning and still needs human playtesting.

## Architecture changes

The reusable `ElementTag` vocabulary is shared by weapon, skill, armor, set, status, and triggered-effect data. Runtime damage continues to carry `DamageElement`, which lets `CombatService`, feedback, statuses, and telemetry process an explicit damage identity. Weapon family and element are separate fields.

`Combatant` now aggregates `PlayerEquipment` and `WeaponSkillExecutor` alongside its existing inventory and attack components. Stats and effect queries combine relic and equipment sources. `BuildAnalyzer` consumes grouped tags from relics, weapon identity, weapon element, skill, armor, and active set tiers without producing a rigid class.

New runtime scripts:

- `WeaponSkillDefinition.cs` and `WeaponSkillExecutor.cs`
- `ArmorDefinition.cs` and `ArmorSetDefinition.cs`
- `PlayerEquipment.cs`

The main modified integration points are `Combatant`, `AttackController`, `CombatService`, `StatusEffectController`, `UpgradeEffectController`, `CorruptionSystem`, `BuildAnalyzer`, `PrototypeCatalog`, `MatchTelemetry`, `PrototypeHud`, `DebugMenu`, `RoomDirector`, `RunManager`, `ActorView`, `EnemyController`, and `PrototypeContentBuilder`.

## Element identities

| Element | Intended play | Implemented proof mechanics |
|---|---|---|
| Fire | AOE, DoT, direct burst | Burn application, threshold/death bursts, fire zones, heavy radial skills |
| Frost | Control, single-target, critical precision | Chill stacks, normal-enemy Freeze, boss vulnerability instead of permanent Freeze, Shatter waves |
| Lightning | AOE, critical proc frequency | Hit charge, critical extra charge, Chain Lightning, Overload/set extra jumps |
| Poison | DoT, spread, sustain | Poison stacks, toxic zones/death clouds, throttled kill recovery |
| Void | AOE and control | Void Mark, persistent rifts, gravity wells, normal-enemy pull; bosses resist forced pull |

These boundaries are expressed through authored tags, statuses, skills, relics, and set effects. Fire receives little hard control; Frost is not a persistent DoT family; Lightning receives no healing; Poison emphasizes attrition rather than precision burst; Void has no broad sustain package.

## Weapon rarity and Weapon Skills

`WeaponRarity` supports Common, Advanced, Rare, Epic, and Legendary. Common weapons preserve basic family behavior. Advanced examples add a minor identity trait. Rare is the first tier allowed to carry a skill. Epic examples combine stronger elemental/status identity with skill interaction. Legendary examples are named, carry lore/passive copy, and use a unique skill profile. Rarity does not apply a universal percentage damage ladder.

`WeaponSkillDefinition` stores ID, player-facing copy, cooldown, minimum rarity, elements/tags, damage kind, delivery mode, radius/duration/movement, projectile count/speed, statuses, optional follow-up-effect data, and VFX/audio hooks. `WeaponSkillExecutor` interprets the same definition for melee dash, area burst, projectile volley, persistent zone, and gravity well. `AttackController` delegates to this executor and keeps corruption's explicit ability override as a later layer.

## Armor and sets

`ArmorDefinition` supports Head, Chest, Gloves, and Boots; rarity; build/element tags; stat modifiers; an elemental passive; a set reference; and a VFX hook. Armor avoids large defense walls. The current pieces use small health/movement values and play-style passives such as elemental amplification, control duration, proc charge, recovery, and cooldown reduction.

Five sets provide four pieces each:

| Set | Element | Two-piece | Four-piece |
|---|---|---|---|
| Ashwalker | Fire | Dash leaves a Fire wake | Wakes gain larger explosive force |
| Winterglass | Frost | Longer Frost control/precision window | Heavy or critical Frost hits release Shatter |
| Stormcaller | Lightning | Better critical charge interaction | Overload gains an extra chain |
| Venomblood | Poison | Poison kills restore throttled health | Death clouds gain damage and infection pressure |
| Riftwalker | Void | Dash rifts gain force | Rift effects pull normal enemies more strongly |

`PlayerEquipment` replaces the item in an occupied slot, groups equipped pieces by set asset, yields the two-piece tier at two pieces, and additionally yields the four-piece tier at four. Both active tiers contribute their tags, modifiers, and effects. The HUD, analyzer, telemetry, combat effects, and debug menu read this one evaluation path.

## Reflection and corruption

Solo reflection analysis includes the selected weapon family/element/skill, relic tags, armor, and set tags. The reflection copies the player's complete weapon definition, then uses the three dominant themes to select at most four representative relics. This creates a readable approximation instead of cloning every proc.

Ash corruption is applied after that copy. It changes faction/presentation, applies profile multipliers and ash behaviors, and may override the active ability, but it does not replace a Frost, Poison, Lightning, or Void weapon identity with Fire. Multiplayer corrupted players retain their equipment directly.

## UI, debug, and telemetry

The HUD journal displays weapon name, rarity, family, element, Weapon Skill, equipped armor, active set tiers, and relic tags using display names. F1 exposes player selection; final boss jump; family/rarity/element selection; skill assignment; two/four-piece set completion; equipment clearing; forced relic theme; BuildAnalyzer output; elemental enemy groups; feedback toggles; invulnerability; and reset.

For a fast manual check, open `TestArena`, press F1, select an elemental Rare-or-higher weapon, equip four Winterglass or another set, close F1, and use E/Y. Reopen F1 to inspect dominant themes. Kill the boss through the debug button and verify the solo reflection title and copied weapon. Status-VFX toggles intentionally affect feedback only.

Local match JSON now records weapon family, rarity, element, skill ID, equipped armor IDs, active set tiers, dominant themes, element/source damage, area/status/critical damage, healing recovery, crowd-control seconds, and proc counts. Nothing is uploaded.

## Automated coverage and balance risks

Edit Mode validates all five rarities/elements, 12 elemental weapons, skill eligibility, both Legendary proofs, all armor slots/sets, two/four-piece evaluation, and complete analyzer input. Play Mode validates a real elemental skill hit/status, four-piece activation, reflection identity, and corruption layering in addition to the existing full run and multiplayer suite.

Known risks require human playtesting: multi-hit skills may scale too strongly with relic procs; stacked two/four-piece effects may exceed intended budgets; Frost boss vulnerability and control windows may trivialize patterns; Poison recovery can swing with enemy density; gravity pull readability and motion comfort need observation; rarity presentation may bias players away from stronger synergies; and reflection approximation may underrepresent unusual hybrid builds.

Recommended v0.4: add an in-run equipment acquisition/comparison flow and saved loadout schema, then conduct repeated solo and 2–4 player balance sessions using the new telemetry. Keep networking as a separate authoritative-transport milestone after equipment ownership and mutation rules are stable.
